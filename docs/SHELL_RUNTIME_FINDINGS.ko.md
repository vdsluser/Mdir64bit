# 명령 치환과 풀메모리 배치 재진입 조사

조사일: 2026-10-22. DOSBox-X 2026.10.01 / DOS 6.22에서 FAT12 작업 이미지와 그 파일을 복사한 호스트 폴더 마운트를 비교했다. 원본·등록 기준 이미지는 보존했다. 합성 명령과 출력만 공개한다.

## `%M`의 단독 치환은 정상

원본 MSET.DOC L364~369는 `%M`/`%m`을 설치 디렉토리로 정의한다. C:\CASE8에서 C:\MDIR\M.EXE를 실행하고 각각 `ECHO L[%M]R`, `ECHO L[%m]R`을 파일로 출력했다. 등록 FAT 이미지에서 둘 다 `L[C:\MDIR\]R`이었다. `/`와 `?` 명령 진입 모두 단독 `%M` 치환은 같았다.

일반 DOS 셸에서는 `ECHO L[%M]R`의 `%M`이 그대로 출력됐다. 환경 변수 M을 ENV_VALUE로 설정해도 같았고, DOS 환경 변수 문법 `%M%`만 ENV_VALUE로 바뀌었다. 같은 환경에서 Mdir의 `%M`은 계속 C:\MDIR\였다. 따라서 단독 치환과 일반 셸의 환경 변수 확장을 구분할 수 있었다. `%F` 대조는 현재 선택 파일인 PARENT.BAT를 반환했다.

등록 파일만 제거한 FAT 작업 이미지에서도 단독 `%M`은 C:\MDIR\였다. 등록판만 가능한 변수라고 판정할 근거는 없었다.

## 기존 빈 값은 특정 조합에서 재현

최초 조사와 같은 조합을 실행했다.

```text
ECHO [!.!][%F][!,][,!][!\][%A][!:][%M][%L] > C:\COMBO.TXT
```

선택 파일이 PARENT.BAT인 이번 등록 FAT 이미지의 결과는 다음과 같았다.

```text
[PARENT.BAT][PARENT.BAT][PARENT][BAT][C:\CASE8\][CASE8][C:][][PARENT.BAT]
```

이 조합은 등록 파일을 제거한 FAT 이미지와 호스트 폴더에서도 `%M` 자리가 비었다. 반면 `%M`과 다른 변수 하나를 조합한 열 가지 짧은 표본은 설치 디렉토리를 반환했다. 그러므로 과거 결과를 `%M`이 항상 실패하거나 등록 제한 때문이라고 설명하면 안 된다.

### 출력 경로 길이만 바꾼 대조

호스트 폴더에서 같은 입력 식을 유지하고 출력 파일명의 길이만 바꿨다.

```text
ECHO [%F][!,][,!][!\][%A][%M] > C:\Q.TXT
```

| 출력 파일명 | 모든 변수가 정상 치환됐다고 계산한 명령 길이 | 실제 `%M` |
|---|---:|---|
| Q.TXT | 69 | C:\MDIR\ |
| QQ.TXT | 70 | C:\MDIR\ |
| QQQ.TXT | 71 | 빈 값 |
| MIN6.TXT | 72 | 빈 값 |

이는 **이 구문·선택 파일·경로에서의 길이 민감 경계**다. 내부 버퍼나 검사 조건을 디스어셈블해 확정한 것은 아니며, 모든 명령의 최대 길이가 70이라고 일반화하지 않는다. 긴 패딩 명령 PAD60은 예상 출력 파일이 없어 정상 치환 결과로 집계하지 않았다.

개별 출력·변수 쌍·대조 길이는 [검증 기록](evidence/2026-10-22/shell-08/verification.json)에 있다. VAR-011의 과거 DIFF는 지우지 않고, 단독 성공과 특정 조합 실패를 함께 기록한다.

## `%B`, `/X`와 호출 문맥

이전 조사에서는 대화형으로 M.EXE를 직접 실행한 뒤 `%B`를 사용하면 생성 배치만 남고 명령이 실행되지 않았다. 이번에는 같은 FAT 이미지에서 부모 배치 호출을 추가해 비교했다.

| 조건 | 결과 |
|---|---|
| `M.EXE /X` → `MEM /C %B` | Mdir로 복귀. MEM에 M 모듈 240바이트가 남음. 이 조건에서 `%B`는 `/X`를 해제하지 않음 |
| 부모 배치에서 `M.EXE` → 자식 RUN.BAT `%B` | 같은 세션에서 자식 실행 후 Mdir로 복귀. RUN 로그 한 행, 자식 작업 경로 C:\CASE8, 자식 MEM에는 M 모듈 없음 |
| 위 복귀한 Mdir를 Alt-X로 정상 종료 | 부모 배치의 이후 줄 실행. RETURNED 출력과 0 반환 코드 범위 확인. TEMP의 (M).BAT는 제거됨 |
| 대화형 셸에서 직접 `M.EXE` → ECHO DIRECT `%B` | Mdir 종료 후 셸 프롬프트. DIRECT.TXT 없음, TEMP의 (M).BAT에 치환된 명령이 남음 |

부모 시험 배치는 아래 형태이며 **생성 배치를 CALL하는 코드는 없다**. 시험에 사용한 부모 파일은 실행 전후 바이트가 같았다.

```bat
@ECHO OFF
C:\MDIR\M.EXE
IF ERRORLEVEL 255 ECHO GE255>>C:\RET.LOG
IF ERRORLEVEL 2 ECHO GE2>>C:\RET.LOG
IF ERRORLEVEL 1 ECHO GE1>>C:\RET.LOG
IF NOT ERRORLEVEL 1 ECHO ZERO>>C:\RET.LOG
ECHO RETURNED>C:\RETURN.TXT
```

자식 RUN.BAT는 RUN 로그 추가, CD 출력, MEM /C 출력만 수행했다. 별도의 복구 래퍼는 실행하지 않았다. 이 결과로 **부모 배치 문맥에서 같은 세션의 자동 실행·재진입**을 확인했다. 단독 호출까지 자동이라고 확장하거나, 다른 MS-DOS/Win95 셸에서도 같다고 주장하지 않는다. 배치 문맥 전달의 내부 구현은 아직 해독하지 않았다.

## 판정과 다음 단계

명령·배치·파일·메모리 관찰 검사 26개를 통과했다. M.EXE와 등록 파일의 바이트는 기준과 같았다. [후속 상태](evidence/2026-10-22/shell-08/status.json)는 VAR-011, VAR-015, CMD-001을 보완하며 전 기능 검증 완료는 아니다.
