# 중복 주석 규칙과 일괄 충돌 정책 조사

조사일: 2026-10-21. 생성 번호로 등록한 FAT12 작업 이미지, DOSBox-X 2026.10.01 / DOS 6.22, `M.EXE /X`에서 관찰했다. ASCII 주석과 합성 8.3 파일만 사용했고 원본 자료와 기준 이미지는 보존했다.

## 중복 주석의 읽기·수정·삭제

초기 C:\DUP\DESCRIPT.ION은 다음과 같았다.

```text
A.TXT first-a
A.TXT last-a
B.TXT first-b
B.TXT last-b
```

| 조작 | 화면·저장 결과 |
|---|---|
| 목록과 A의 Alt-Enter 편집 창 열기 | 마지막 항목 last-a/last-b가 표시됨. 편집 창에도 last-a가 입력되어 있음 |
| A 주석을 edited-a로 저장 | A의 기존 두 항목을 제거하고 `A.TXT edited-a` 한 행 기록. 수정하지 않은 B의 중복 두 행은 유지 |
| 프로그램 재실행 | edited-a와 last-b 표시 유지 |
| B 주석을 Ctrl-Y로 비우고 Enter | B 파일은 유지되고 주석은 표시되지 않음. 저장 파일에는 **`B.TXT ` 빈 주석 행 하나가 남음** |
| 별도 DEL 폴더에서 중복 주석을 가진 A 파일 자체 삭제 | A 파일과 A의 주석 두 항목이 모두 없어짐. KEEP.TXT와 그 주석은 유지 |

즉, 이번 표본에서는 편집 대상 이름만 하나로 정리하며 파일 전체의 중복을 일괄 제거하지 않았다. 빈 값 저장은 주석 행 제거와 동일하지 않고, 파일 자체 삭제는 같은 이름의 항목들을 제거했다.

증거: [처음 목록](evidence/2026-10-21/description-06/s001-duplicate-read.txt), [편집 창](evidence/2026-10-21/description-06/s002-duplicate-edit.txt), [수정 후](evidence/2026-10-21/description-06/s003-edited.txt), [재실행](evidence/2026-10-21/description-06/s004-restart.txt), [빈 주석 저장](evidence/2026-10-21/description-06/s005-delete-comment.txt), [파일 삭제 후](evidence/2026-10-21/description-06/s019-file-deleted.txt).

저장 전후 원문과 해시는 [파일 검증 기록](evidence/2026-10-21/description-06/file-verification.json)에 있다. 빈 주석 행은 행 끝 공백까지 포함한 원문으로 판정했다. 이 규칙을 다른 프로그램의 4DOS 주석 처리나 Unicode 이름에 그대로 적용하지 않는다.

## All과 sKip_all

원본과 대상의 A/B.TXT 내용은 각각 SOURCE-A/B와 TARGET-A/B로 달랐고 파일 크기는 각각 10바이트였다. 두 파일을 선택한 한 복사 작업에서 첫 충돌 창의 정책을 선택했다.

- **All**: 추가 충돌 창 없이 두 대상 모두 원본 내용으로 바뀌었다. 대상의 기존 주석 두 행은 유지되고 새 주석 두 행이 추가되어, A와 B 모두 같은 이름의 주석이 두 개가 됐다.
- **sKip_all**: 추가 충돌 창 없이 종료했고, 두 대상의 내용과 DESCRIPT.ION 전체 바이트가 시작 전과 같았다.

[All 충돌 창](evidence/2026-10-21/description-06/s008-all-conflict.txt), [All 후](evidence/2026-10-21/description-06/s009-all-result.txt), [sKip_all 후](evidence/2026-10-21/description-06/s012-skip-all.txt). 단일 Skip과 일괄 sKip_all은 서로 다른 선택으로 검증했다.

## Newer의 시간 비교

세 파일을 선택한 한 복사 작업에서 첫 충돌 창의 Newer를 한 번 선택했다. 다른 내용·같은 크기의 파일로 비교했으며 다음 파일에서 추가 충돌 창 없이 처리됐다.

| 파일 | 원본 수정 시각 | 대상 수정 시각 | 결과 |
|---|---|---|---|
| A.TXT | 2024-01-02 12:00:00 | 2024-01-01 12:00:00 | 원본이 더 새로워 덮어씀 |
| B.TXT | 2024-01-02 12:00:00 | 2024-01-02 12:00:00 | 시간이 같아 대상 유지 |
| C.TXT | 2024-01-01 12:00:00 | 2024-01-02 12:00:00 | 원본이 더 오래돼 대상 유지 |

이 표본은 원본 시간이 **엄격하게 더 늦을 때만** 덮어쓰는 결과다. A 주석은 기존+새 항목이 남았고 B/C는 기존 대상 주석만 유지됐다. [입력 목록](evidence/2026-10-21/description-06/s014-newer-ready.txt), [첫 충돌 창](evidence/2026-10-21/description-06/s015-newer-conflict.txt), [처리 후](evidence/2026-10-21/description-06/s016-newer-choice.txt).

시각은 FAT 표본에 지정한 값이며 실제 시간대 변환을 검증한 실험이 아니다. 2초 단위 FAT 시각의 경계·다른 크기·숨김/읽기전용 속성·시간 누락은 미검증이다.

## 원장과 전환 계획 반영

파일 내용·주석·등록 파일의 22개 검사를 통과했다. 복사 원본의 내용은 유지됐으며 원본 ZIP과 폴더의 37개 지문도 기존 인벤토리에 대조한다. [ID별 후속 상태](evidence/2026-10-21/description-06/status.json)는 DESC-001/002, FILE-002/006의 부분 관찰이다. 앞선 [단일 충돌·진행 후 취소 조사](CONFLICT_RUNTIME_FINDINGS.ko.md)와 합쳐 여섯 충돌 선택의 정상 표본을 확보했으나, 기능 행 전체를 검증 완료로 바꾸지는 않는다.

P1의 주석 호환 검토에서는 **읽을 때의 마지막 항목 선택**, **편집 대상 항목 정리**, **빈 주석 행 보존 여부**, **덮어쓰기 시 중복 추가**를 분리한다. 원본 파일 보존 모드와 새 Windows판의 정규화 정책은 아직 결정하지 않았다. 모든 저장에 자동 정규화를 적용하면 원본의 처리 방식과 차이가 생길 수 있다.

P0-11은 ASCII·정확히 같은 이름의 규칙을 확인한 상태다. 대소문자·공백/따옴표 이름·한글·주석 길이 경계·중복 항목 삭제 취소는 남아 있다. 다음 우선 실험은 P0-06의 **기존 파일 덮어쓰기 또는 이동 도중 취소**와 **용량 부족 경고에서 계속 진행한 부분 실패**다. 이 결과를 새 파일 복사의 취소 결과로 대신하지 않는다.
