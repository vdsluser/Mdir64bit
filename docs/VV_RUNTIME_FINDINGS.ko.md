# 등록판 VV 기능 조사 2차

조사일: 2026-10-21. 등록번호 생성 검증에 사용한 FAT12 이미지의 별도 복사본에서 VV 3.10을 실행했다. 원본 `mdir/`와 기준 이미지는 수정하지 않았다. 에뮬레이터는 DOSBox-X 2026.10.01 SDL1 x64, DOS 6.22, VGA 640×480, 고정 10000 cycles다. 실행 시 `/N`으로 화면보호만 끈 상태다.

## 저장의 의미와 파일 검증

F2는 문서 본문 저장이 아니라 보기 설정 저장이다. 종료 후 FAT 이미지에서 추출해 비교한 VV.EXE는 길이 66023바이트가 같고 **0기반 파일 오프셋 66020, 66021의 두 바이트만 변경**됐다. 이것은 이 표본에서의 결과이며 전체 설정 포맷을 해독한 것은 아니다. 실행 파일 수정은 원본 프로그램이 작업 복사본에 수행했다. 기준/변경 해시는 [파일 검증 기록](evidence/2026-10-21/vv-02/file-verification.json)에 있다.

다섯 입력 표본과 MDIR.REG는 실행 전후 바이트가 같았다. 원본 폴더 및 ZIP의 37개 해시는 기존 인벤토리와 별도로 대조한다. DOS 날짜·시간은 에뮬레이터 시각이며 실제 처리 속도나 Windows 호환 성능의 근거로 사용하지 않는다.

## 검색·본문 저장 여부

이번에 읽은 VV.DOC의 메인 화면 명령 목록과 실제 F12 메뉴에서 검색 또는 문서 본문 저장 명령을 발견하지 못했다. 따라서 검색/편집/본문 저장을 원본 VV의 확인된 기능으로 계획하지 않는다. 숨은 명령의 부재까지 입증한 것은 아니다. Windows판에 검색이나 헥스 보기를 추가한다면 원본 호환과 별도인 신규 요구로 구분해야 한다.

## 재현 표본과 입력 주의점

[파일 검증 기록](evidence/2026-10-21/vv-02/file-verification.json)의 `fixtures`에는 파일별 전체 합성 바이트의 hex와 SHA-256이 있다. Python의 `bytes.fromhex`로 복원할 수 있다. LONG.TXT는 긴 행 끝 표식과 다음 줄을 구분하며, TABS.TXT는 탭을 확장한 공백으로 미리 바꾸지 않는다. 한글 표본은 짧은 KS 완성형/Johab 사례이고 CP949 확장 문자 전체에 대한 시험은 아니다.

키 입력은 기존 `probe.py`를 통한 게스트 BIOS 키 큐다. 문자만 있는 BIOS 워드 `0x0034`는 탭 폭을 바꾸지 못했고, 숫자 4의 스캔코드가 있는 `0x0534`는 바꿨다. 숫자 8은 `0x0938`을 사용했다. 입력 도구의 무반응을 기능 부재로 판정하지 않는다. 그래픽 모드의 문자 메모리 덤프는 화면 증거로 사용할 수 없어 실제 대상 창 캡처를 대조했다.

## 남은 조사와 전환 반영

다음 원본 조사 순서는 등록판의 디렉토리 작업·주석 동반 처리·풀메모리 실행 차이, MF/MCOPY의 취소·오류·Format OFF다. VV는 한자/외부 글꼴, 색상·해상도, F8/F4, 문서 처음/끝·대용량·잘못된 인코딩·마우스·기타 CLI 옵션이 남아 있다.

P6의 읽기 기능은 인코딩 감지와 수동 선택, 탭 정지점, 줄바꿈과 수평 이동, 보기 설정 보존을 분리해 설계한다. Windows판 설정은 별도 사용자 설정 파일을 후보로 삼고, VV처럼 실행 파일 끝에 쓰는 방식을 그대로 승계하지 않는다. 아직 Windows 구현 언어와 UI 기술을 확정한 단계는 아니다.
