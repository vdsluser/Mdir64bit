# MF/MCOPY 취소·오류·Format OFF 조사

조사일: 2026-10-21. DOSBox-X 2026.10.01 / DOS 6.22에서 FAT16 C:와 1.44MiB FAT12 A:/B: 이미지로 실행했다. C:는 생성 등록번호로 만든 MDIR.REG를 사용했다. 실제 디스크 장치는 사용하지 않았다. 원본·기준 이미지는 보존하고 작업 복사본만 변경했다.

## MCOPY

| 실험 | 관찰과 파일 검증 | 증거 |
|---|---|---|
| 읽기 전 W | Write OFF, `Cannot write` 오류 | [오류](evidence/2026-10-21/disk-04/d001-write-before-read.txt) |
| R 직후 Esc | 메뉴 복귀, Write OFF. A:/B: 모두 시작 전과 해시 동일 | [읽기 중단](evidence/2026-10-21/disk-04/d002-read-cancel.txt) |
| 정상 R 완료 | Write ON | [완료](evidence/2026-10-21/disk-04/d006-read-done.txt) |
| 대상 B:, Format OFF, W 직후 Esc | 메뉴 복귀, Write ON 유지. B: 해시가 시작 전과 같음 | [설정](evidence/2026-10-21/disk-04/d008-format-off.txt), [초기 쓰기 중단](evidence/2026-10-21/disk-04/d009-write-cancel.txt) |
| 재실행·다시 R 완료 후 B:에 Format OFF 쓰기 | 메뉴 복귀. A:/B: 전체 1474560바이트 동일, A:는 시작 전 내용 유지 | [완료](evidence/2026-10-21/disk-04/d017-write-done.txt) |

시작 시 A:의 SENT.TXT는 `A` 8192개, B:는 `B` 8192개였다. 단순히 같은 빈 디스크 둘을 비교하지 않았다. Format OFF 복사 후 두 이미지의 SHA-256은 `452e7006cb97b0f773631d5e4fd3cffb1f05171cdf31b15daedd4f9d06ae0c62`다. [전체 이미지 지문 및 검증](evidence/2026-10-21/disk-04/image-verification.json).

이번 결과로 **이미 포맷된 같은 크기 이미지에 Format OFF 상태로 복사가 가능**함을 확인했다. 화면 옵션과 결과를 관찰했으며 BIOS 포맷 호출을 추적해 0회임을 증명한 것은 아니다. 이전의 Format ON 성공과 함께 설명서의 ‘아직 지원 않음’ 문구만으로 현재 바이너리의 기능을 배제할 수 없음을 보여준다.

초기 쓰기 중단 때 변경이 없었다는 결과는 실제 쓰기가 진행된 뒤 원상복구된다는 뜻이 아니다. 이번에는 뒤늦은 쓰기 중단·부분 변경·취소 후 동일 버퍼 재사용을 검증하지 않았다. 같은 용량 한 사본만 확인했고 복수 사본·다른 용량·CLI·쓰기 방지·미디어 제거는 남아 있다.

## MF

### 일반 포맷 중 초기 Esc

일반 실행의 포맷이 빠르게 끝나 Esc 시점을 구분하기 어려워, 공식 디버거 명령 `BPINT 13 05`로 BIOS 포맷 트랙 호출에 중단점을 설정했다. [작업 중 화면](evidence/2026-10-21/disk-04/d027-mf-format-break.txt)에서 `Press ESC to stop`을 확인했다. 중단점을 지우고 게스트 BIOS 큐에 Esc를 넣어 재개하자 [기본 메뉴로 복귀](evidence/2026-10-21/disk-04/d028-mf-active-cancel.txt)했다. 종료 후 이미지 해시는 기준과 같았다. [명령 기록](evidence/2026-10-21/disk-04/mf-breakpoint-method.json).

실행 파일을 패치하지 않았지만 디버거가 시간을 바꾸므로 실제 하드웨어의 반응 속도나 중단 지연을 검증한 것은 아니다. 조기 중단 한 사례이며, 데이터가 이미 변경된 뒤의 취소·복구까지 보장하지 않는다.

### 0으로 채운 미포맷 이미지의 Quick

F5로 Quick을 선택한 뒤 시작했다. 원본 설명서 MF.DOC L93은 포맷되지 않은 디스크에서 퀵포맷할 때 Disk read error를 설명하지만, 이 입력에서는 `Quick Format` 상태에 머물렀다. 10초 이상 관찰한 뒤 Esc를 넣어도 정상 메뉴 복귀나 해당 오류 창을 확인하지 못했다. 실행을 종료했고 이미지 전체는 여전히 0이었다.

[Quick 선택](evidence/2026-10-21/disk-04/d018-mf-mode.txt), [시작](evidence/2026-10-21/disk-04/d019-mf-quick-blank.txt), [Esc 후](evidence/2026-10-21/disk-04/d021-mf-quick-escape.txt). 이는 **예외 관찰**로 남긴다. 정상 퀵포맷 성공, 정상 오류 처리 또는 영구적인 정지의 원인까지 확정한 것은 아니다. 원본의 BPB 0 처리와 에뮬레이터 BIOS 동작을 추가로 분석해야 한다.

## 상태와 다음 순서

[ID별 후속 상태](evidence/2026-10-21/disk-04/status.json)는 FORMAT-001, COPY-001, COPY-002의 부분 관찰이다. 기능 행 전체의 검증 완료 수는 늘리지 않았다. 선택한 텍스트 증거와 이미지 지문만 공개하며 원본 바이너리·원본 등록정보·메모리 덤프는 공개하지 않는다.

Windows판의 이미지 작업은 취소와 원상복구를 구분하고, 기록된 범위·부분 실패·재시도 가능 여부를 결과에 포함해야 한다. 미포맷 입력은 유효한 BPB/용량인지 먼저 확인하는 수용 기준을 P8 계획에 반영한다. 물리 장치 지원은 아직 확정하지 않았다.

다음은 P0의 173개 기능에 대한 최신 후속 상태와 미해결 항목을 통합하는 작업이다. 우선순위는 MCD 교차 드라이브 복사, 풀메모리 자동 재진입, MF Quick 예외, 외부 압축 도구·Win95 환경 부재를 분리하고 P1 진입 전에 필요한 조사 범위를 정하는 것이다. P0 전체를 완료로 표시하지 않는다.
