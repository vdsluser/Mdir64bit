# Mdir III 기능 분석 및 Windows 11 x64 전환 계획

작성: 2026-10-20 · 상태: 문서 근거 초안 / 원본 실행 검증 대기

## 1. 목표와 완료 기준

사용자가 제공한 Mdir 원본으로 기능을 조사하고, Windows 11에서 동작하는 네이티브 x64 프로그램의 전환 순서를 정한다. 키보드 중심 조작, 파일 목록, MCD/QCD, 프로그램 연결과 압축파일 관리라는 사용 흐름을 보존한다. 이번 산출물은 분석·계획 문서이며 제품 코드가 아니다.

‘모든 기능 문서화 완료’는 아래를 모두 만족했을 때 선언한다.

1. 설명서·도움말·설정 메뉴·실행 메뉴의 항목을 기능 ID에 연결한다.
2. 각 기능의 정상·취소·오류·재실행 후 상태를 격리된 원본 환경에서 재현한다.
3. 증거 파일과 원본/환경 해시를 남기고, 문서와 다른 동작 및 판본 제한을 해소한다.
4. 각 기능을 유지·현대화·대체·제외 중 하나로 판정하고 이유를 검토한다.

현재 1번의 문서 기반 목록화 단계다. 실행 메뉴만의 항목과 문서에 없는 동작은 추가 발견될 수 있다. 기능 ID의 실행 상태는 모두 미검증이다.

## 2. 조사 결과와 전환 방식

로컬 `mdir/`에는 M.EXE, MSET.EXE, VV.EXE, MFF.EXE, MF.EXE, MCOPY.EXE 및 지원 파일이 있다. M.DOC와 VV.DOC는 3.10을 표기한다. 실제 바이너리 버전·등록 상태·문서와의 일치는 실행 후 확정한다. 원본 파일 지문은 [인벤토리](ORIGINAL_INVENTORY.ko.md)를 따른다.

소스 파일은 발견되지 않았다. M.EXE는 MZ 헤더이고 유효한 PE 헤더는 확인되지 않는다. DOS용이라는 동봉 문서와 일치하지만 CPU 모드·컴파일러·압축기·언어는 아직 확정하지 않는다.

64비트 Windows는 16비트 프로그램 실행을 지원하지 않는다. [Microsoft 공식 설명](https://learn.microsoft.com/en-us/troubleshoot/windows-client/application-management/x64-windows-not-support-16-bit-programs). 헤더 변경이나 단순 재컴파일로 해결할 수 있는 상황이 아니다.

| 접근 | 장점 | 한계 | 판단 |
|---|---|---|---|
| 에뮬레이터에 원본을 넣어 배포 | 원본 조작을 빠르게 재현 | 원본은 DOS 프로그램, 현대 파일시스템·보안·통합에 제약 | 원본 비교용 환경으로 사용 |
| 기계어를 해석해 직접 이식 | 내부 알고리즘 추적 가능 | 소스 없음, DOS/BIOS 의존, 분석 비용 큼 | 불명확한 포맷·동작만 선택 분석 |
| 관찰한 기능을 x64로 재구현 | Windows 파일 API·Unicode·현대 경로 처리 가능 | 세부 동작의 회귀검증 필요 | 권장 |

권장 구조는 화면/키 입력 → 의미 명령 → 파일·검색·압축·실행 서비스이다. 원본 화면 상태와 동작 명세를 먼저 고정하고 구현 언어와 UI 기술은 짧은 시제품 비교 후 결정한다. C++/Win32, C# 데스크톱, 콘솔 UI는 검토 후보이며 확정 사항이 아니다.

## 3. 기능 범위

세부 항목과 근거 위치는 [기능 추적표](FEATURE_CATALOG.ko.md)를 따른다. 원본 설명서의 한 줄 제한과 일반용/등록판 차이는 Windows판의 새 제한으로 자동 승계하지 않는다.

| 영역 | 원본 동작 | 전환 원칙 |
|---|---|---|
| 메인 목록 | 1~6열·자동열, 경로·용량·선택 수·주석·속성·색상, 정렬·필터 | 단일 목록 중심을 우선 보존; 임의로 2패널 UI로 바꾸지 않음 |
| 탐색·선택 | 방향키·페이지·문자 검색·다음 찾기·드라이브 이동·선택 반전·패턴 | 포커스와 선택 집합을 분리, 설정별 Ins/Del 대상 구분 |
| 파일 작업 | 복사·이동·삭제·일괄 이름 변경·폴더 생성·속성·인쇄 | 충돌 정책·부분 실패·취소·진행률 명세부터 고정 |
| MCD/QCD | 트리 탐색·검색·재검색·폴더 작업·용량·캐시, 즐겨찾기 10개 | 대규모 트리·취소·변경 감지, 부모 셸 디렉토리 변경은 별도 래퍼 |
| 프로그램 실행 | 28개 펑션키, 복수 명령 메뉴, 확장자 연결, 실행 전 편집 | 파일명/인자/작업 경로를 분리; Windows 예약키 충돌 명시 |
| 도스명령 | 명령 편집·이력·변수·경로 삽입·이전 실행 화면 | cmd/PowerShell 연동으로 현대화; 명령 언어의 차이는 명시 |
| 주석 | DESCRIPT.ION, 일괄 편집, 파일 작업에 동반, 긴 이름 변환 | 호환 형식 조사, 긴 이름을 기본 표시; 손실 없는 왕복 우선 |
| 압축 | 11종 형식·SFX 인식, 내부 트리/평탄화, 생성·추가·추출·삭제·실행 | ZIP부터; 형식별 읽기/쓰기/외부도구 지원을 따로 판정 |
| MSET | 설정 저장·이전 설정 읽기·색상·팔레트·실행 연결·입력 설정 | 새 설정 포맷; 원본 CFG/COL 읽기는 별도 호환 계층 |
| MFF | 다중 패턴·드라이브 검색, 결과 정렬·선택·삭제·보기·실행·위치 이동 | 비동기 검색·취소·접근 거부 처리 |
| VV | 조합형/완성형/영문·이진 보기, 한자·글꼴·탭·줄바꿈·표시 저장 | Unicode 변환·인코딩 수동 선택; 내장 글꼴 재사용 별도 판단 |
| MF/MCOPY | 플로피 포맷·검사·방향·복제·복수 사본 | 일반 파일 복사와 구분; 이미지 파일 대상으로 먼저 검증 |
| 기타 | HCONV, HE.COM, DSCMAN.EXE, MOUSE.COM/INI, PIF/ICO | HCONV는 이력 근거; 나머지 역할·호출관계는 미확정 조사 항목 |

## 4. 먼저 해결할 불명확성

- 주석 길이: M.DOC 제한 표는 80글자, 주석 본문은 길이 제한 없음이라고 한다. 실제 읽기·편집·저장 한계를 바이트/문자 단위로 분리 측정한다.
- 압축 내부 트리 전환: 도움말은 Alt-백틱, 본문 일부는 Alt-작은따옴표로 기재한다. 실제 키 이벤트로 확인한다.
- 숫자패드 `/`: 도움말은 같은 확장자 선택/취소, 본문 요약표는 패턴 취소라고 적는다. 일반 `/` 명령 진입과도 구분한다.
- MCOPY Format: 메뉴 설명은 아직 미지원, 후속 문장은 설정 가능처럼 적는다. 동작 확인 전 지원으로 표시하지 않는다.
- 일반용/등록판: 디렉토리 작업·주석 동반·풀메모리·MF 오류에 판본 차이가 기재되어 있다. 제공 바이너리의 상태를 확인하되 등록 우회는 분석 범위에 넣지 않는다.
- M.CFG는 설명서상 구판 텍스트 → 신판 전용 편집 형식으로 바뀌었다. 한 가지 포맷으로 가정하지 않는다. %L은 업데이트 이력에서 추가되어 변수 표에 누락되어 있다.
- 실제 긴 이름 지원은 Win95/DOS 7 환경 의존이다. DOS 에뮬레이터만의 결과를 Win95 동작으로 일반화하지 않는다.

## 5. 전환 순서와 단계별 종료 조건

의존 순서: P0 → P1 → P2 → P3 → P4 → P5 → P6 → P7 → P8. 단계 안에서는 작게 나눠 검토한다. 일정은 실행 조사 후 산정한다.

| 단계 | 작업·예정 산출물 | 필요한 확인 | 종료 조건 |
|---|---|---|---|
| P0 원본 기준선 | 격리 DOS 환경, Win95 비교 환경, `docs/evidence/`, 기능별 관찰 기록 | 모든 메뉴·설정·CLI·정상/취소/오류·판본별 차이 | 모든 ID를 관찰 또는 미지원/차단 사유로 판정; 미해결 목록 검토 |
| P1 포맷·아키텍처 확정 | `docs/formats/`, `docs/architecture/`, UI 시제품 비교 기록 | CFG/COL/HIS/TREE/DESCRIPT.ION, 키 충돌·한글 IME·크기 변경 | UI/언어 선정, 데이터 경계·호환 정책·수용 기준 승인 |
| P2 읽기 전용 탐색 MVP | `src/`의 목록·탐색·선택·정렬·필터·테마와 `tests/` | Unicode/긴 경로/10만 항목/권한 오류/네트워크 끊김 | Windows 11 x64에서 읽기 전용 기본 흐름 통과 |
| P3 파일 작업 | 파일작업 서비스·진행상태·충돌 처리·이름 변경 | 취소/디스크 부족/잠긴 파일/대소문자 이름 변경/교차 볼륨 이동 | 작업 전후 트리·내용 해시 일치, 원본 손실 없이 부분 실패 설명 |
| P4 MCD/QCD·설정·주석 | 트리·캐시·즐겨찾기·설정 저장·주석 연동 | 재시작·오래된 캐시·재분석 지점 순환·접근 거부 | 탐색/저장 복원 통과, 주석과 파일 작업 일관성 |
| P5 실행·명령 연결 | 확장자·28키·다중 명령·변수·셸 이력·래퍼 | 공백/한글/따옴표/특수문자 인자, 취소·종료 코드·작업경로 | 테스트용 자식 프로세스가 받은 인자·경로가 명세와 일치 |
| P6 MFF·VV·HCONV | 검색·결과에서 작업·텍스트/이진 미리보기·변환 | 최대 20 패턴 호환, 중단, 조합형/완성형/Unicode/잘못된 바이트 | 원본 표본 비교와 손실·오인식 표시 확인 |
| P7 압축 | ZIP 읽기/추출 → 생성/추가/삭제 → 실행 → 구형 형식 어댑터 | 경로 탈출·암호·손상·대용량·취소·외부도구 부재 | 형식별 지원표 작성, 압축 성공 확인 후에만 원본 삭제 |
| P8 레거시·출시 | MF/MCOPY 이미지 대체 검토, 제외 목록, x64 패키지·도움말 | PE Machine AMD64/64비트 프로세스, 깨끗한 Windows 11, 전체 회귀 | 기능별 판정 누락 0; 설치/실행/복구 검증·배포 내용 검토 |

P2~P8의 구체 파일명과 API는 P1에서 결정한다. 현재 단계에서 구현 세부를 확정해 소스가 있는 것처럼 계획하지 않는다. 새 파일 작업은 먼저 실패·취소·충돌 사례를 정의하고 테스트한 후 구현한다.

## 6. 선택적 리버싱 작업

1. 해시로 원본 고정 → MZ 헤더·재배치·오버레이·문자열 확인 → 압축 여부 조사.
2. 원본 메뉴/입력/파일 변화를 관찰해 호출 흐름과 파일 포맷 가설을 만든다.
3. MSET의 설정 한 항목만 바꾼 복제본들을 비교해 오프셋·길이·체크섬 가설을 검증한다. 원본은 수정하지 않는다.
4. 행동 관찰로 해결되지 않는 지점만 디스어셈블·디버그한다. DOS/BIOS·파일 API·프로세스 실행 경계를 우선 표시한다.
5. 디컴파일 결과는 추정으로 표기하고 관찰과 대조한다. 원본 기계어의 직접 변환을 완료 목표로 삼지 않는다.

## 7. Windows판 정책 제안 — 구현 전 검토

- 파일 크기·용량은 64비트 값, Unicode 이름을 기본으로 한다. 경로 처리, 네트워크, 심볼릭 링크/정션, 접근 거부를 명세에 포함한다.
- 삭제는 휴지통을 기본 후보로 검토한다. 원본의 즉시 삭제 및 루트 삭제 허용 설정은 그대로 기본값으로 옮기지 않는다.
- BIOS 파킹·캐시 드라이버 직접 제어·실행 파일에 설정 쓰기·XMS/EMS는 대체/제외 후보다. MF/MCOPY의 물리 디스크 지원은 별도 범위로 결정한다.
- 압축 파일 실행은 명시적 사용자 실행 동작을 통해서만 한다. 임시 폴더 격리·경로 탈출 차단·정리와 실패 복구를 설계한다.
- 저장소는 공개 상태다. 원본 바이너리·설명서 전문·등록정보·내장 글꼴을 자동 공개하지 않는다. 새 코드 라이선스 및 원본 자산 재배포 여부는 배포 전 결정한다.

## 8. 지금 가능한 다음 작업

P0를 수행해 이 문서의 ‘문서 근거’를 ‘관찰 근거’로 확장한다. 실제 실행 없이 전체 기능 확인 완료라고 선언하지 않는다. [검증 절차](VALIDATION_PLAN.ko.md)에 따라 메뉴 스크린샷·조작·파일 차이를 기록한 다음 P1 기술 결정을 진행한다.
