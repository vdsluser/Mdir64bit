# 기존 대상 덮어쓰기·이동 취소와 용량 부족 조사

조사일: 2026-10-22. 생성 번호로 등록한 FAT12 C:/D: 이미지와 DOSBox-X 2026.10.01 / DOS 6.22, `M.EXE /X`를 사용했다. 세 사례는 서로 독립된 작업 이미지이며 원본 자료와 기준 이미지는 보존했다. 실제 사용자 파일과 물리 장치는 사용하지 않았다.

## 기존 대상이 있는 복사·이동 중 취소

원본 C:\CASE7\BIG.BIN은 `bytes(range(256)) * 2048`의 524288바이트, 기존 대상 D:\DST\BIG.BIN은 `U` 131072바이트였다. 주석도 각각 source-big과 target-old로 구분했다.

충돌 창에서 OverWrite를 선택한 뒤 DOS 쓰기 호출 `BPINT 21 40`에 중단점을 걸었다. 진행 창을 관찰하며 쓰기를 진행시킨 다음 중단점을 지우고 BIOS 큐에 Esc를 넣어 재개했다. 실행 파일은 패치하지 않았고, 시간 측정이나 실제 하드웨어 반응 속도 검증은 아니다.

| 사례 | 원본 | 대상 파일 | 대상 주석 |
|---|---|---|---|
| Alt-C 덮어쓰기 도중 Esc | 내용·주석 유지 | 새 파일뿐 아니라 **기존 대상도 복원되지 않고 없음** | BIG.BIN target-old가 남음 |
| Alt-M 교차 드라이브 이동 도중 Esc | 내용·주석 유지 | **기존 대상이 복원되지 않고 없음** | BIG.BIN target-old가 남음 |

복사와 이동 모두 메뉴로 복귀했다. 이미지 비교에서 새 원본 패턴이 기록된 512바이트 섹터가 각각 380개·253개 확인됐다. 따라서 단순히 쓰기 전에 취소된 사례가 아니다. 각 수치는 디버거로 제어한 해당 중단 시점의 결과이며 일반적인 고정 기록 크기가 아니다.

이 결과는 **메뉴 복귀·불완전 파일 삭제가 기존 대상의 복원을 뜻하지 않음**을 보여준다. 대상이 없는데 예전 주석만 남는 불일치도 확인했다. 원본 파일은 유지되었으므로 원본까지 유실됐다고 해석하지 않는다.

증거: [복사 충돌](evidence/2026-10-22/partial-07/w002-conflict.txt), [복사 진행](evidence/2026-10-22/partial-07/w004-progress.txt), [복사 취소](evidence/2026-10-22/partial-07/w005-cancelled.txt), [이동 충돌](evidence/2026-10-22/partial-07/m002-conflict.txt), [이동 진행](evidence/2026-10-22/partial-07/m004-progress.txt), [이동 취소](evidence/2026-10-22/partial-07/m005-cancelled.txt).

## 용량 부족 경고에서 계속 진행

별도 D:에는 600KiB FILL.BIN과 기존 KEEP.TXT/주석을 두고 BIG.BIN은 두지 않았다.

1. 복사 전 `Not enough free space for COPY. Continue?`에서 Yes를 선택했다.
2. 쓰기 처리 중 `Not enough free space in writing drive D:, Continue?`가 표시됐다.
3. 두 번째 경고에서 No를 선택하자 `COPY failed / BIG.BIN`이 표시됐다.
4. 종료 후 대상 BIG.BIN은 없었고 KEEP.TXT·주석·FILL.BIN과 원본 BIG.BIN·주석은 유지됐다.

이미지 비교에서 바뀐 섹터는 8, 20, 25, 2571이었다. 앞 세 개는 FAT/루트 메타데이터 영역이고 2571은 새 MCD 트리 캐시의 시작 섹터다. 이 사례에는 복사 본문 패턴이 기록된 섹터가 없었다. 따라서 **쓰기 경로의 용량 오류와 정리는 확인했지만, 본문이 일부 기록된 뒤의 용량 부족을 확인했다고 집계하지 않는다.**

[사전 경고](evidence/2026-10-22/partial-07/p002-warning.txt), [Yes 후 쓰기 경고](evidence/2026-10-22/partial-07/p003-continue.txt), [실패 표시](evidence/2026-10-22/partial-07/p004-write-failure-no.txt).

첫 가설은 본문이 일부 기록된 뒤 실패했을 것이라는 것이었으나, 원시 이미지 비교로 구분했다. 변경 섹터 수만으로 복사 본문 기록을 판단하지 않는다. 두 번째 경고의 Yes·매체 교체·여러 파일 중 일부 성공·같은 드라이브 이동·읽기전용 대상은 남아 있다.

## 증거와 판정 범위

[파일 검증 기록](evidence/2026-10-22/partial-07/file-verification.json)의 원본·대상·주석·기존 파일·등록 파일·이미지 비교 검사 23개가 관찰 결과와 일치했다. 이 검사의 통과는 **기존 대상 유실을 포함한 관찰 사실이 재현됐다는 뜻**이며 제품의 데이터 보호 기준 통과가 아니다.

[ID별 후속 상태](evidence/2026-10-22/partial-07/status.json)는 FILE-001/003/004, DESC-002의 부분 관찰·예외다. 기존 단일/일괄 충돌 성공 사례와 [새 파일 진행 후 취소](CONFLICT_RUNTIME_FINDINGS.ko.md)를 그대로 보존하며 기능 전체 검증 완료로 올리지 않는다.

## Windows판 파일 작업 수용 기준에 반영할 항목

원본의 대상 유실 동작을 Windows판의 기본 동작으로 승계하지 않는 방향을 계획한다. 구체 구현은 P1/P3에서 검토하되 다음을 시험 가능한 기준으로 남긴다.

- **기존 대상 보호**: 취소·공간 부족·쓰기 실패 시 기존 대상 내용과 주석이 유지돼야 한다. 임시 대상에 기록하고 검증 후 교체하는 방식은 설계 후보이며 아직 구현하지 않았다.
- **이동 원본 보호**: 대상 기록과 검증이 끝나기 전에는 원본 삭제를 완료 처리하지 않는다. 교차 볼륨에서 부분 실패를 숨기지 않는다.
- **파일과 주석의 일관성**: 파일 교체·주석 갱신·실패 복구를 같은 작업 결과로 추적한다. 파일과 별도 주석 파일의 변경이 자동으로 하나의 원자적 연산이 된다고 가정하지 않는다.
- **정확한 결과 표시**: 성공·취소·실패·복구 실패와 남은 임시 파일을 구분한다. ‘취소됨’만 표시하고 이전 상태가 보존됐다고 추정하게 하지 않는다.

아직 Windows 제품 구현은 시작하지 않았다. 다음 조사 묶음은 P0-01/04의 명령 변수 `%M`, `%B`, `/X`와 부모 셸·배치 재진입을 비교하는 것이다. 파일 작업의 남은 경계는 P0-06에 명시하고 P0 전체 완료와 구분한다.
