# P0 통합 검토와 다음 조사 순서

갱신: 2026-10-21. 현재 단계는 P0 원본 관찰이며 Windows판 제품 구현은 미착수다. [173개 기능의 현재 상태](CURRENT_STATUS.ko.md)와 [JSON 원장](evidence/current-status.json)을 기준으로 판단한다. 보고서의 작성 순서를 검증 완료 순서로 해석하지 않는다.

## 현재 결론

등록번호 생성·원본 등록, VV의 표본 표시와 설정 저장, 파일과 주석 동반 처리, MCD의 일부 폴더 작업, 배치 기반 메모리 실행, MF/MCOPY의 일부 정상·취소·예외 사례를 관찰했다. 과거 등록 차단 8개는 해소됐지만 VIEW-004는 여전히 미실행이다.

173행 중 **부분 관찰 40, 부분 관찰·예외 2, 개별 사례 관찰 7, 메뉴만 관찰 79, 미실행 43, 외부 도구 차단 1, 문서와 차이 1**이다. 전체 기능 검증 완료는 0행이다. 이 값은 기능 행의 상태 분포이며 진행률이 아니다. 한 행에 들어 있는 조작 수와 경계 조건이 서로 다르다.

## 다음 실행 묶음

1. **핵심 파일 작업 묶음**: P0-02/03/06을 우선한다. 현재 파일 작업은 성공 경로 중심이므로 충돌·취소 후 주석과 데이터의 일관성을 먼저 명세한다.
2. **명령 실행 묶음**: P0-01/04를 함께 조사한다. `%M`·`%B`·`/X`·부모 셸을 같은 합성 명령으로 비교한다.
3. **설정과 포맷 표본 묶음**: P0-08과 미실행/메뉴만 관찰한 ID를 작은 그룹으로 나눠 채운다. 변경 전후·취소·재실행을 한 세트로 남긴다.
4. **외부 환경·레거시 묶음**: P0-07/09/05/10은 도구·환경 필요 조건을 먼저 정리하고, 미해결 상태나 제외 후보의 이유를 문서화한다.

각 묶음은 새 실행 폴더와 합성 표본을 사용한다. 실제 사용자 파일·물리 디스크를 시험 대상으로 삼지 않는다. 새 관찰을 원장 생성기의 입력에 추가하고 현재 상태를 다시 생성한다.

## P1 진입 판단

**현재 P1 진입과 제품 설계 확정은 보류한다.** 자료 조사와 포맷 표본 확보는 계속할 수 있지만, 구현 언어/UI를 확정하거나 P2 제품 코드를 시작한 것으로 표시하지 않는다. 기존 P0→P1→P2 순서를 유지한다.

| 조건 | 현재 | 다음 충족 기준 |
|---|---|---|
| 기존 ID와 근거 연결 | 충족 | 173개 ID·원본 근거·실행 이력을 유지하고 새 발견은 별도 ID 검토 |
| 증거와 상태의 일관성 | 충족 | 통합 생성기 `--check`, 링크·해시·원본 지문 대조 유지 |
| 핵심 조작의 정상/취소/오류 명세 | 미충족 | P0-02/03/06의 결과·경계·남은 한계를 판정 |
| 판본·문서 차이와 환경 차단 정리 | 일부 충족 | P0-01/04 및 외부 환경 차이를 해결하거나 명시적 미해결/제외 판정 |
| 유지·현대화·대체·제외의 기능별 검토 | 미충족 | 현재 단계별 후보를 ID별 판정으로 구체화. 원본 미관찰과 Windows 제외 결정을 구분 |

P1에서는 CFG/COL/HIS/TREE/DESCRIPT.ION 호환 정책, Unicode/긴 경로/한글 입력, 명령과 서비스 경계, UI/언어 후보 시제품을 비교한다. 아직 선택이나 개발 일정은 확정하지 않는다.

## 통합 원장 갱신 방법

저장소 루트에서 다음을 실행한다.

```powershell
python tools/analysis/build_status.py
python tools/analysis/build_status.py --check
```

생성기는 최초 173행과 VV·등록판 작업·디스크·파일 충돌 후속 상태를 입력 순서로 병합하고, 등록 보고서의 SET-007 관찰을 명시적으로 연결한다. 모든 관찰의 범위·출처·증거를 `observations`에 보존한다. UNTESTED는 검증 성공으로 바꾸지 않으며, VIEW-004의 해소된 등록 차단은 NOT_RUN으로 정정한다.

자동 생성 결과는 CURRENT_STATUS.ko.md와 evidence/current-status.json이다. 새 보고서를 추가하면 입력 목록을 검토해 갱신한다. `--check`는 입력 ID 중복·알 수 없는 ID·증거 누락·출력 불일치를 검사하고 파일을 쓰지 않는다. 사례의 실제 성공이나 스크린샷 의미까지 자동 판독하는 도구는 아니다.
